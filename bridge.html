From KineNest to ROS 2

Assemble a small two-node system. The browser runs real Python or compiles real C++; the workspace, build, shell and ROS graph are educational models aligned with the ROS 2 Jazzy beginner workflow.

Reference: ROS 2 Jazzy. KineNest does not run native ROS 2, DDS, colcon, ament or Linux processes.

Your route through the system

  1. Inspect ros2_ws/src, choose Python or C++, and create my_robot_pkg.
  2. Inspect package.xml, the build file, and both node sources. Edit and save a source file.
  3. Build from the workspace root; use a build error to understand the package definition.
  4. Source each terminal that will run your package. Start publisher and subscriber manually in separate terminals.
  5. Inspect ros2 node list, ros2 topic list and ros2 topic echo in another terminal. Stop both programs.
  6. Build and run the launch file. One configuration fault prevents communication. Diagnose and correct it, rebuild, then relaunch.
  7. Check that one launch command starts both nodes, applies a parameter and remapping, and carries real messages.

          What do these commands do?
          cd src
          Enters src, where ROS packages are created.
          ros2 pkg create
          Creates the package files in the current src directory.
          cd ..
          Moves from src to the workspace root before building.
          colcon build
          Checks the package and compiles its code into the modeled install space.
          source ~/ros2_ws/install/local_setup.bash
          Makes installed packages discoverable in this terminal.
          ros2 run PACKAGE EXECUTABLE
          Starts one built node program.
          ros2 launch PACKAGE FILE
          Starts the nodes and configuration declared in a launch file.
          ros2 node list · ros2 topic list · ros2 topic echo
          Shows live nodes, topics and messages so you can diagnose the running system.

          Workspace terminals

          Each terminal has its own sourced environment. Processes share one live graph. Ctrl+C or Stop ends processes owned by that terminal.

            What moves to native ROS 2?
            Workspace and package structure, metadata, source code, build configuration, sourcing, ros2 run, ros2 launch and graph inspection transfer. Native ROS 2 adds Linux processes, full ament/CMake and colcon, DDS/RMW, real hardware and timing. Continue with the official Jazzy tutorials.
