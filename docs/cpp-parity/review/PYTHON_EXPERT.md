## P2 follow-up: TF report association is a legacy limitation

CA-04 in `CHECKER_ADVERSARY.md` identifies a real source-level language difference: Python `report_transform`/`report_relative` attach the current sensor sample, whereas C++ normalizes these reports to a null sample. In a Python sensor callback, the shared adapter takes its sample branch and `assessCourse` discards these report kinds without TF credit. Timer callbacks avoid this path.

**This is not a newly introduced Python regression.** Baseline `96986c8` already contains the same Python report binding and the same adapter routing/assessment behavior. C++ now accepting that alternate design exposes a pre-existing Python limitation. No browser reproduction was run, and no P0/P1 classification is supported. A future focused two-language test can move a valid TF lookup/report into an odometry callback, then normalize TF report routing if callback-style alternatives are intended to be supported. Preserve sensor association for range, sectors and pose. No implementation reopening is recommended during this freeze.
