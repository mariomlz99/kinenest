# Existing beginner API audit

Reviewed representative starter/reference code and the current teaching adapters. Decisions concern API patterns; the adapters remain documented educational subsets. No broad formatting rewrite was made.

| Concept | Existing KineNest pattern | Jazzy official pattern | Newer distro difference | Decision | Reason |
|---|---|---|---|---|---|
| Publisher | `create_publisher(String/Twist, topic, 10)` / typed `create_publisher<T>` | [Python pub/sub](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Publisher-And-Subscriber.rst), [C++ pub/sub](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Cpp-Publisher-And-Subscriber.rst) | Lyrical retains basic form | Keep | Beginner API shape is sound; QoS integer is a teaching simplification |
| Subscription/callback | Python callback and C++ typed callback/lambda | Same pub/sub tutorials | No material change found | Keep | Correct beginner pattern; one C++ 2.1 hint may need a bound member callback as noted in earlier educator review |
| Timer | `create_timer` / `create_wall_timer` | Same pub/sub examples | No material change found | Keep | Class-owned callback patterns are current |
| Service/client | Trigger `call_async` and response callback | [Jazzy Python service/client](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Service-And-Client.rst) uses `create_service`, `create_client`, `wait_for_service`, `call_async` and future completion | [Lyrical service tutorial](https://github.com/ros2/ros2_documentation/blob/lyrical/source/ROS-Framework/client-libraries/Working-with-Client-Libraries/Writing-A-Simple-Py-Service-And-Client.rst) retains these APIs and explicitly cautions against `spin_until_future_complete` inside a callback | Keep bounded API | Foundations omits native service discovery and full `.srv` type support; async callback completion avoids the warned pattern |
| Parameters | `declare_parameter`, `get_parameter`, update at runtime | [Jazzy parameter class](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Beginner-Client-Libraries/Using-Parameters-In-A-Class-Python.rst) declares a typed default, reads `get_parameter(...).get_parameter_value()` and uses `set_parameters` | [Lyrical parameter tutorial](https://github.com/ros2/ros2_documentation/blob/lyrical/source/ROS-Framework/client-libraries/Working-with-Client-Libraries/Using-Parameters-In-A-Class-Python.rst) retains these calls; its sample uses `with rclpy.init()` and handles `ExternalShutdownException` | Keep bounded API | Launch parameter injection follows the declared parameter model; KineNest supports a subset of value types. The newer context-manager lifecycle is a distinct idiom, not required for this Jazzy-aligned bridge |
| Actions | Goal/feedback/result/cancel through teaching server | [Jazzy Python action client](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Intermediate/Writing-an-Action-Server-Client/Py.rst) uses `ActionClient.send_goal_async`, goal response and `get_result_async` | [Lyrical action tutorial](https://github.com/ros2/ros2_documentation/blob/lyrical/source/ROS-Framework/interfaces/actions/Working-with-actions/Writing-an-Action-Server-Client/Py.rst) retains goal, feedback and result API shape | Keep bounded API | Current Foundations includes cancellation and a course server, but does not teach full native action server structure |
| TF | `lookup_transform(target, source, ...)` / C++ buffer counterpart | [Jazzy tf2 listener](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Intermediate/Tf2/Writing-A-Tf2-Listener-Py.rst) uses `Buffer`, `TransformListener` and target/source/time lookup | [Lyrical tf2 listener](https://github.com/ros2/ros2_documentation/blob/lyrical/source/ROS-Framework/client-libraries/Working-with-Client-Libraries/Tf2/Writing-A-Tf2-Listener-Py.rst) retains the buffer/listener and latest-time lookup shape | Keep bounded API | KineNest's planar latest-only TF is explicitly disclosed; it does not buffer ten seconds of network transforms |
| Launch | Existing course only links native transition | [Jazzy launch tutorial](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Tutorials/Intermediate/Launch/Creating-Launch-Files.rst) | Lyrical reorganized docs | Add bounded lesson | New integration gap |

The direct docs site was access challenged in this environment. Jazzy and Lyrical source branches of the official documentation were checked for these beginner API shapes. This audit covers representative course patterns; it does not establish native equivalence for every KineNest shim API.
