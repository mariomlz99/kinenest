Transition to native ROS 2 Jazzy

You have already assembled, built and launched a two-node package in KineNest. Carry that same package and command sequence to a Jazzy installation.

Open the final Core workspace to review and export your package

Move your package to Jazzy

Export the Python or C++ package ZIP and extract my_robot_pkg into ~/ros2_ws/src. Check package.xml and install its declared native dependencies before building.

source /opt/ros/jazzy/setup.bash
cd ~/ros2_ws
colcon build
source install/local_setup.bash

Start each executable in its own sourced terminal, as you did in the bridge. Stop both before using the launch file.

ros2 run my_robot_pkg publisher
ros2 run my_robot_pkg subscriber
ros2 launch my_robot_pkg system_launch.py
ros2 node list
ros2 topic list
ros2 topic echo /bridge_chatter

How the same files connect

package.xml declares the package and dependencies. setup.py with setup.cfg, or CMakeLists.txt for C++, defines executable installation. The node source files provide the behavior. launch/system_launch.py starts both installed executables with a parameter and topic remapping.

A wrong remapping produces two live topics without a connected publisher and subscriber. Inspect the graph, correct the launch file, rebuild and relaunch, just as in KineNest.

What changes on a real robot?

Native ROS 2 adds Linux processes, full ament and colcon, DDS/RMW discovery, complete QoS and TF behavior, real drivers and hardware timing. KineNest models these boundaries for learning.

The exported starter packages were built, run and launched on native Jazzy during Core validation. Your edits and hardware setup still need their own native tests.
